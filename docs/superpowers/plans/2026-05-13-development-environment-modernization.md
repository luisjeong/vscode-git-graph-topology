# Development Environment Modernization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make installs, builds, linting, tests, and CI reproducible on a modern Node.js development baseline.

**Architecture:** Keep the extension-host, webview, and test source layout intact. Modernize the dependency graph, lockfile, CI workflow, and compatibility fixes in small commits so toolchain problems are isolated from behavior-preserving code changes.

**Tech Stack:** VS Code extension API, TypeScript, Jest, ts-jest, ESLint, npm, GitHub Actions, Node.js 24 LTS.

---

## File Structure

- Modify: `package.json`
  - Add Node engine metadata.
  - Update dev dependency versions.
  - Replace `vsce` with `@vscode/vsce`.
  - Keep the existing script names so VS Code tasks continue to work.
- Create: `package-lock.json`
  - Generated by `npm install` after dependency updates.
- Modify: `.github/workflows/build-and-test.yml`
  - Update GitHub Actions versions.
  - Use Node 24.
  - Use `npm ci`.
- Modify: `jest.config.js`
  - Move ts-jest config out of deprecated `globals` if required by upgraded ts-jest.
- Modify: `.eslintrc.json`
  - Keep legacy config if ESLint 10 still accepts it with `-c`.
  - Make only targeted rule/config changes required by the upgraded parser and plugin.
- Modify: `src/avatarManager.ts`
  - Only if investigation confirms production URL construction is relying on older parsing behavior.
- Modify: `tests/avatarManager.test.ts`
  - Update assertions or fixtures only after confirming the intended URL behavior.

- [ ] **Step 2: Add a focused failing assertion for GitHub avatar URLs with no path**

In `tests/avatarManager.test.ts`, keep the GitHub fixture:

```ts
mockHttpsResponse(200, '{"author":{"avatar_url":"https://avatar-url"}}');
```

Keep the expected request as:

```ts
expect(spyOnHttpsGet).toHaveBeenCalledWith({
	hostname: 'avatar-url',
	path: '/?size=162',
	headers: { 'User-Agent': 'vscode-git-graph' },
	agent: false,
	timeout: 15000
}, expect.anything());
```

Use `/?size=162` rather than `/&size=162`; a URL without an existing query string should receive a `?size=162` query.

- [ ] **Step 3: Fix GitHub avatar URL construction**

In `src/avatarManager.ts`, replace:

```ts
let img = await this.downloadAvatarImage(avatarRequest.email, commit.author.avatar_url + '&size=162');
```

with:

```ts
let img = await this.downloadAvatarImage(avatarRequest.email, appendQueryParam(commit.author.avatar_url, 'size', '162'));
```

Add this helper near the other file-level helpers:

```ts
function appendQueryParam(rawUrl: string, key: string, value: string) {
	const separator = rawUrl.indexOf('?') >= 0 ? '&' : '?';
	return rawUrl + separator + encodeURIComponent(key) + '=' + encodeURIComponent(value);
}
```
